# botkit-farm: секреты и доступы

## Модель угроз

Ферма берёт **чужой репозиторий**, исполняет его код и рисует по нему картинки.
Отсюда ровно пять опасностей — и все пять закрыты кодом, а не намерением.

| Опасность | Что могло случиться | Что стоит |
|---|---|---|
| Настоящий токен Telegram в окружении | «Локальный стенд» одним запросом уезжает в сеть, бот начинает отвечать живому человеку | `security.assert_fake_token` — прогон не начинается |
| Исходящие подключения бота | Код бота уходит в интернет во время прогона (телеметрия, чекаут, что угодно) | `quarantine` — разрешён только loopback, **в процессе бота** |
| Запись вне рабочих каталогов | Бот создаёт файл в `$HOME`, правит `~/.ssh`, лезет в чужой репозиторий | `quarantine` — `PermissionError` + запись в отчёт |
| Путь репозитория/кейса/фикстуры | `../../` в поле `source` или `fixture` — и ферма читает/пишет вне проекта | `security.safe_join`, санитайзер имени репо |
| Секрет в отчёте | Бот читает свой `.env` и присылает токен в ответе; отчёт уезжает в git навсегда | `security.scrub` + `reports/` в `.gitignore` |

## 1. Токен

Проверяется **не только** `TELEGRAM_BOT_TOKEN`, а любая переменная, похожая на
токен (`\d{6,}:[A-Za-z0-9_-]{20,}`). Причина: бот мог оставить ключ в `.env` или
в переменной с другим именем, и проверка одного известного имени была бы фикцией.

Разрешён только префикс `424242` — фейковый токен стенда.

```
$ botkit-farm doctor
  [OK  ] token: настоящего токена Telegram в окружении нет
```

Проверка живёт в `tests/test_security.py::test_токен_под_другим_именем_тоже_ловится`
— то есть она обязана уметь падать.

## 2. Egress — перехват стоит в двух местах

Запрет на исходящие подключения ставится **дважды**:

* `security.block_egress` — в процессе фермы. Сеть снимается ровно дважды и оба
  раза осознанно: клонирование репозитория (`source.prepare`) и установка
  зависимостей бота (`env.ensure_env`).
* `quarantine` — **в процессе бота**, постоянно.

Второе сделано не для надёжности «на всякий случай». Подпроцесс бота запускается
чистым интерпретатором и подмены из процесса фермы **не видит** — запрет
распространялся ровно на тот участок прогона, где бот ещё не работал.

Канал разрешён один — loopback: фейковый Bot API и Redis. Нарушения не
проглатываются: бот получает `PermissionError`, а список попыток попадает в
результат кейса (иначе бот, поймавший исключение, отработал бы «успешно», и
попытка уйти в сеть осталась бы незамеченной).

## 3. Карантин: запись по белому списку

`quarantine` разрешает запись только в каталоги прогона — код бота, его база,
временный каталог — и сравнивает **реальные** пути (`realpath`), а не написанные.
Поэтому не проходят `../`, симлинк наружу и соседний каталог с общим префиксом
(`bot-backup` — не подкаталог `bot`). Перехватываются `open`, `io.open`, `os.open`
по флагам записи, `os.mkdir` и `os.makedirs`; чтение не трогается.

Отказ всегда с текстом: путь, список разрешённых каталогов и подсказка
`BOTKIT_FARM_QUARANTINE`. Боту, которому каталог действительно нужен, нужен
способ его получить, а не молчаливый отказ.

Расширить список можно переменной:

```bash
BOTKIT_FARM_QUARANTINE=/opt/данные:/srv/шрифты botkit-farm run
```

## 4. Песочница ОС: bubblewrap

Карантин ограничивает средствами интерпретатора. Против кода, который их обходит
(`ctypes`, прямой syscall), нужен запрет на уровне ядра — это `sandbox.wrap`:
в namespace попадают только каталоги прогона, `/usr` и `/etc` монтируются **на
чтение**, `--die-with-parent` не даёт боту пережить ферму.

Сеть остаётся общей (`--share-net`): фейковый API и Redis живут на loopback
снаружи namespace, а запрет исходящих подключений обеспечивает карантин.

```bash
BOTKIT_FARM_SANDBOX=1 botkit-farm run     # включить
```

Локально выключено — слой мешает отладке. **В CI включено всегда**: там код
бота чужой и появляется без ведма того, кто его принёс. Включённая, но
недоступная песочница — ошибка, а не тихий отказ.

Состояние показывает `doctor`: «песочник недоступен», «доступен, но выключен»,
«включена через bubblewrap» — три разных ответа.

## 5. Пути и секреты

Клон бота и venv живут в `bots/` и `envs/`. Локальный путь **копируется**, а не
используется на месте: бот во время прогона пишет в свой каталог (база, логи,
миграции), и эти записи не должны оказываться в рабочем дереве разработчика.

`safe_join` запрещает абсолютные пути и `..`; имя репозитория из URL
санитайзером очищается от слешей и `..`.

`scrub` вычищает из отчёта токены, приватные ключи, AWS/ключи Stripe,
`api_hash` и пароли. Вычистка идёт **до** записи на диск — секрет не должен
попасть в файл даже на секунду.

Дополнительно: `reports/` в `.gitignore`, а `gitleaks` в pre-commit ловит то,
чего не знает `scrub`.

## Ограничения (честно)

- **Карантин не видит нативный код.** Расширение, пишущее файл через syscall,
  минует перехваты Python. Против него работает только `bubblewrap`, и то не
  против всех случаев.
- **Песочница умеет только `bwrap`.** `unshare`, `podman` и `docker` видны в
  `doctor` как backend'ы, но обёртка прогона реализована для `bwrap`: контейнер
  требует настройки сети и томов, это отдельный объём работы.
- **Локально песочница выключена** — осознанный компромисс ради отладки.
- **Зависимости ботов ставятся из pip и git** по их объявлению, без проверки
  подписей. Это доверяет авторам ботов — они ваши.
- **`bandit`/`ruff S` смотрят на ферму**, а не на код ботов: бот — чужой проект.

## Где это проверено

| Что | Тест |
|---|---|
| запись в `$HOME` запрещена | `tests/test_quarantine.py::test_запись_в_домашний_каталог_запрещена` |
| обход через `..` и симлинк | `::test_выход_из_каталога_точками_запрещён`, `::test_симлинк_из_каталога_наружу_не_пролез` |
| egress наружу запрещён | `::test_подключение_наружу_запрещено` |
| loopback остаётся рабочим | `::test_подключение_к_локальному_порту_разрешено` |
| нарушения доезжают до результата кейса | `tests/test_engine.py::test_ошибка_запуска_не_теряет_нарушения` |
| песочница собирается правильно | `tests/test_sandbox.py::test_системные_каталоги_только_на_чтение` |
| включённая песочница без bwrap — ошибка | `::test_включённая_но_непоставленная_песочница_это_ошибка` |
