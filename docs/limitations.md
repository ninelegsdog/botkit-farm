# Ограничения (честно)

Список нужен не для красоты: заявление «тестирует любого бота» без оговорок
врёт, а врёт в маркетинге — и это хуже, чем короткий список ограничений.

## Сегодня не поддерживается

| Ограничение | Почему так | Что нужно |
|---|---|---|
| Нет inline-режима | `answerInlineQuery` не обслуживается | отдельный маршрут |
| Пачки-альбомы (`sendMediaGroup`) не проверяются | на незнакомый метод фейковый API отвечает `True`; набор вложений не собирается | `sendMediaGroup` и проверка набора |
| Нет Telegram Login | вход через Telegram не обслуживается | — |
| Нет платежей | шаг платежа в кейсе не выразить вовсе: модель шага умеет `send`/`click`/`pick`/`callback`/`press` и не имеет «оплата прошла», а фейковый API не обслуживает `sendInvoice`/`createInvoiceLink`. Класс «оплата прошла → доступ открыт» офлайн не проверяется ни для одного бота | шаг `pay` в схеме кейса + заглушка инвойса и доставка сообщения `successful_payment`; без владельца у класса платёжного провайдера класс остаётся непокрытым |
| Нет фоновых задач | нет планировщика APScheduler/задач | сценарий с ожиданием по времени |
| Нагрузку не меряет | прогон — один сценарий, без замеров времени и нагрузки | нагрузочный сценарий |
| HTTP-эндпоинты бота не тестируются | вебхук-режим шлёт update POST'ом, но произвольные маршруты бота не дёргаются | сценарии HTTP-запросов к боту |
| Только aiogram 3 | адаптеры написаны под aiogram; сторонние подключаются точкой `botkit-farm.adapter`, но переводники под PTB/pyrogram/telethon не написаны | переводники; десериализацию уже проверяет `raw: true` (`feed_raw_update`) |
| Песочница ОС не включена локально | мешает отладке на машине разработчика; в CI включается всегда (`BOTKIT_FARM_SANDBOX=1`) | — решение осознанное, подробности в [security.md](security.md) |
| Карантин не ловит нативный код | перехват на уровне Python; нативное расширение пишет через syscall | bubblewrap — включён в CI, но и он не закрывает все случаи |
| Песочница умеет только bubblewrap | `unshare`/`podman`/`docker` видны в `doctor`, но требуют настройки сети и томов | обёртка для контейнерного backend'а |
| Windows не поддерживается | окружение бота ищется по POSIX-пути `bin/python` (на Windows venv кладёт `Scripts\python.exe`), песочник — только `bwrap`/`unshare`/`podman`/`docker`, блокировка сборки — `fcntl` | пути окружения по `sys.platform`, свой backend песочницы |
| На macOS нет песочницы | bubblewrap опирается на Linux namespaces, которых в macOS нет; `BOTKIT_FARM_SANDBOX=1` там честно падает с `SecurityError` | изоляция на macOS — только карантин и запрет egress; CI на macOS гоняет тесты фермы, но не полные прогоны бота |
| Подделка `callback_data` проверяется только на отказ | шаг `callback` разрешён лишь под тегом `security`/`edge` и обслуживает refusal-проверки: кейс не должен *создавать* состояние атакой, иначе отчёт показывает путь, которого у клиента в бою нет | осознанное решение, а не дыра; запись через сырой callback — отдельное обсуждение |

Проверено, что поддерживается: текст, медиа (фото, документы, голос, стикеры,
видео, анимации), inline-кнопки (по подписи, позиции и сырыми `callback_data`),
группы и треды, несколько участников сценария и режим webhook.

Про платежи отдельно, чтобы читатель не сделал ложный вывод из таблицы.
«Нет платежей» — это не «оплата в ботах не проверена, но работает». Переход
*оплата прошла → доступ открыт* **не покрыт ни одним автоматическим проверяющим**
ни в ферме, ни в юнит-тестах ботов (0 из 9). Платёжный код есть у четырёх, и в
нём нет закрытого пути:

| бот | что есть | чего нет |
|---|---|---|
| `botkit-docuflow` | `pre_checkout_query` и `successful_payment` (`src/docuflow/handlers.py:236`, `:246`) | кейса «после оплаты документ открыт» |
| `botkit-bookingbot` | `attach_payment_handlers` из ядра (`src/app.py:37`) и `expected_amount` для pre_checkout (`src/booking/service.py`) | кейса «после оплаты запись создана» |
| `botkit-store` | машина состояний заказа `pending_payment` → `paid` и `mark_paid` (`src/store/service.py:124`) | **`mark_paid` не вызывается ниоткуда** — перехода «заказ оплачен» в коде нет |
| `botkit-membership` | ничего: хэндлер `mem:subscribe:` (`src/membership/handlers.py:98`) вызывает `activate_subscription` (`:111`) напрямую | платёжного шага нет вообще — клуб открывается нажатием кнопки |

Ферма не может закрыть класс, который бот не реализует, и не может выразить
платёж в кейсе — поэтому это **явное** ограничение с названным владельцем, а не
пробел в молчании. Решение, кому принадлежит класс (бот-уровневый контракт или
отдельная задача на постановку платежа) — за владельцем, см. В2 плана.

## Честно о качестве кадра

Кадр показывает **поведение бота, воспроизведённое стендом**. Это не скриншот
живого клиента: подложка нарисована/снята вручную, сценарий написан человеком.
Подпись «Демо-интерфейс» обязательна — снимать её нельзя, иначе кадр станет
вводящим в заблуждение.

## Честно о кейсе

Кейс проверяет **то, что в нём написано**. Слабый кейс, проходящий по счастливому
совпадению, — не баг фермы. Признак слабости: `optional` на большинстве шагов
или `silent` там, где ответ ожидаем.
